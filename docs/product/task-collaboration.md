# 작업 협업

Engrove의 작업 상세는 작고 실행 가능한 프로젝트 작업을 위한 협업 화면입니다. 보드는 상태를 빠르게
훑는 역할에 집중하고, 카드를 열면 보드를 떠나지 않은 채 편집, 근거, 활동, 댓글, 멘션, 구독과 작업
관계를 관리합니다.

![작업 보드 위에서 열린 상세 패널](/screenshots/task-detail.png)

_카드에는 읽기에 필요한 정보만 남기고, 수정과 협업은 상세 패널에서 수행합니다._

## 안정적인 작업 키

각 작업은 프로젝트 안에서 변경되지 않는 번호와 `MOTOR-42` 같은 사람이 읽을 수 있는 키를 받습니다.
프로젝트 키와 작업 번호는 동시에 생성 요청이 들어와도 고유하게 배정됩니다.

카드, 달력, 상세, 관련 작업, 검색과 링크 복사에는 안정적인 키를 표시하고 UUID는 내부 참조에
사용합니다. 작업 API의 `{taskId}`에는 UUID나 대소문자를 구분하지 않는 키를 사용할 수 있습니다.
다른 프로젝트의 키는 권한 검사를 통과한 뒤에도 찾을 수 없음으로 처리되어 프로젝트 범위를 넘지
않습니다.

## 중복 생성 방지와 복제

브라우저와 API의 생성 요청에는 idempotency key가 포함됩니다. 응답을 받지 못해도 24시간 안에 같은
본문과 키로 다시 요청하면 새 번호나 알림을 만들지 않고 기존 결과를 반환합니다. 같은 키에 다른
내용을 보내면 명시적인 충돌을 반환합니다.

활성 작업은 상세 상단이나 카드 우클릭 메뉴에서 복제할 수 있습니다. 복제는 즉시 저장하지 않고 일반
생성 폼을 수정 가능한 초안으로 엽니다.

- 복사: 설명, 우선순위, 라벨, 담당자, 마감일과 상위 작업
- 새로 시작: 제목 접두사와 워크플로 최초 상태
- 복사하지 않음: 댓글, 하위 작업, 근거 링크, 첨부, 활동, 구독자와 현재 상태

새 작업은 원본과 `relates_to` 관계를 원자적으로 만들기 때문에 유사 작업의 이유는 남기면서 과거
증거를 복제하지 않습니다. 저장하지 않은 편집이나 댓글·링크 초안이 있으면 먼저 저장하거나 버려야
복제할 수 있습니다.

## 사양 실패에서 후속 작업 만들기

실패한 사양 평가에는 툴팁이 있는 하나의 후속 작업 아이콘이 표시됩니다. 처음 성공한 요청은 높은
우선순위 작업을 만들고 다음 근거를 함께 연결합니다.

- 대상 레코드와 필드
- 평가와 측정 결과
- 전문 레코드와 지원 데이터셋
- 생성·평가 감사 이벤트

동시에 여러 번 눌러도 프로젝트 트랜잭션 잠금으로 하나의 작업에 수렴합니다. 성공 후 아이콘은 안정적
작업 키와 상세 링크로 바뀝니다.

## 명령 검색과 바로가기

전역 명령 검색은 macOS에서 `⌘K`, 그 외 환경에서 `Ctrl+K`로 열립니다. 현재 워크스페이스의 활성
프로젝트, 작업, 테이블과 일반 이동 명령을 검색하며 `MOTOR-42` 같은 정확한 키를 우선합니다.

작업을 선택하면 별도 편집 페이지로 이동하지 않고 기존 보드 위에 상세 패널을 엽니다. 상세 패널에서
`W`는 구독 전환, `M`은 댓글 작성기로 이동합니다. 입력 필드에서는 일반 타이핑 동작을 우선합니다.

링크 복사 아이콘은 UUID나 일시적인 보드 필터가 아닌 작업 키 기반의 정규 URL을 만듭니다. 기존 UUID
북마크도 열린 뒤 작업 부분만 정규 키로 교체하며 저장 필터와 뷰 상태는 유지합니다.

## 저장하지 않은 변경 보호

작업 생성과 상세 편집은 명시적으로 저장합니다. 필드, 담당자, 상위 작업, 댓글 초안, 외부 링크,
멘션이나 관계 후보가 바뀌면 저장되지 않음 표시가 나타납니다.

닫기 버튼, 배경, Escape, 관련 작업 또는 주요 일정으로 이동할 때 변경을 버릴지 확인합니다. 브라우저
종료도 기본 미저장 경고를 사용합니다. 성공한 저장은 해당 요청이 커밋한 초안만 지웁니다.

## 댓글, 멘션과 구독

- 작업 생성자와 현재 담당자는 개인 자동 구독 설정에 따라 작업을 구독합니다.
- 로그인한 멤버는 누구나 개인적으로 구독하거나 해제할 수 있습니다.
- Contributor와 Reviewer도 댓글을 작성할 수 있습니다.
- 작성자는 자신의 활성 작업 댓글만 수정할 수 있습니다.
- 댓글 수정에는 마지막으로 읽은 행 버전이 필요하며 충돌 시 덮어쓰지 않습니다.
- 멘션은 활성 조직 멤버로 제한하고, 수정 시 새로 추가된 멘션에만 알립니다.
- 행위자 자신에게는 자신의 변경 알림을 보내지 않습니다.

알림 센터는 읽지 않은 수를 표시하고 하나 또는 전체를 읽음 처리할 수 있습니다. 알림을 선택하면
정확한 워크스페이스와 프로젝트의 작업 상세를 엽니다. 개인 설정에서는 배정, 멘션, 구독 활동과
마감일 알림을 각각 제어합니다.

담당자와 검토자 선택기는 조직 전체 명단을 미리 받지 않습니다. 처음에는 제한된 페이지를 요청하고,
이름이나 이메일을 입력하면 서버에서 검색합니다. 한 페이지 밖의 멤버도 대규모 조직에서 선택할 수
있습니다.

## 내 작업

워크스페이스의 **내 작업**은 여러 프로젝트의 개인 실행 대기열입니다. 로그인한 사용자에게 배정된
활성 미완료 작업만 보여 주며 프로젝트 보드를 복제하지 않습니다.

기한 초과, 7일 이내와 차단됨을 빠르게 필터링할 수 있고, 검색·긴급도·우선순위·정렬 상태는 URL에
남습니다. 기본 순서는 기한 초과, 해결되지 않은 차단, 가까운 마감일, 우선순위와 최근 수정 순으로
주의가 필요한 항목을 앞에 둡니다.

## 라벨과 유연한 분류

작업에는 프로젝트 범위의 라벨을 최대 12개까지 지정할 수 있습니다. 라벨은 Unicode NFKC 소문자로
정규화하고 문자, 숫자, 점, 하이픈과 밑줄만 허용합니다.

상태가 워크플로 단계를 표현한다면 라벨은 `safety`, `supplier`, `simulation`처럼 여러 단계를 가로지르는
관심사를 표현합니다. 카드는 앞의 세 개를 작게 표시하고 상세에서는 전체 목록을 보여 줍니다. 검색과
저장 필터에도 라벨을 사용할 수 있습니다.

## 외부 근거와 파일 첨부

작업 상세에는 내부 UUID 대신 제목과 HTTP(S) URL만으로 외부 근거를 추가할 수 있습니다. 링크를
추가하면 프로젝트 외부 자료와 작업 연결이 한 트랜잭션에서 생성됩니다. 서비스 이름은 기본적으로 URL
호스트를 사용하며 API에서는 외부 ID, 버전, 확인일과 메모를 더할 수 있습니다.

연결을 제거해도 외부 자료와 감사 이력은 삭제하지 않고 작업과의 연결만 끊습니다. 보관된 원본도 과거
작업에서 사라지지 않고 상태와 함께 표시됩니다.

작은 맥락 파일은 근거 영역에 놓거나 업로드 아이콘으로 선택합니다. Engrove는 별도 첨부 저장소를
만들지 않고 체크섬을 검증하는 기존 파일 업로드를 사용합니다. 한도는 100 MiB이며, 연결에는
`file.upload`와 `task.update`가 필요합니다. 외부 시스템이 관리하는 원본은 파일을 복제하지 말고 URL
근거를 사용하세요.

## 관계와 차단

한 프로젝트 안에서 다음 관계를 연결할 수 있습니다.

- **차단함** (`blocks`)
- **차단됨** (`is blocked by`)
- **관련됨** (`relates to`)

보드와 상세는 아직 완료되지 않은 차단 작업 수를 보여 주지만 관계가 상태를 자동으로 바꾸지는
않습니다. 차단 관계는 방향성 비순환 그래프이며, 프로젝트 잠금과 재귀 검사를 통해 동시에 생성되는
순환도 막습니다.

## 상위 작업과 하위 작업

실행 가능한 작업은 같은 프로젝트에서 한 단계의 하위 작업을 묶을 수 있습니다. 하위 작업이 다시
상위 작업이 되거나 활성 하위 작업이 있는 작업이 다른 작업의 하위가 되는 것은 허용하지 않습니다.

상위 작업은 사용자가 입력한 퍼센트 대신 완료된 하위 작업 수를 `완료 / 전체`로 표시합니다. 상위
작업에 활성 하위 작업이 있으면 보관할 수 없고, 보관된 상위 작업이 복원되기 전에는 하위 작업도
복원할 수 없습니다.

## 주요 일정과 연결

주요 일정 하나에는 같은 프로젝트의 활성 작업을 최대 200개까지 연결할 수 있습니다. 타임라인은
연결 작업의 `완료 / 전체`와 파생 막대를 표시합니다. 작업 상세에서도 날짜, 상태와 주요 일정으로
돌아가는 링크를 확인합니다.

작업이 모두 끝나도 주요 일정을 자동 완료하지는 않습니다. 승인, 납품이나 계약일처럼 준비 작업 이후
책임자의 명시적인 판단이 필요할 수 있기 때문입니다.

## 반복 분류와 일괄 변경

보드는 프로젝트 전체 순위를 저장합니다. 카드나 열에 놓아 상대 위치를 바꾸고, 키보드로는
`Alt+Up/Down`을 사용합니다. `Alt+Left/Right`은 상태 전환을 유지합니다. 마지막으로 읽은 행 버전을
사용해 이동과 전환을 하나의 직렬화된 트랜잭션으로 저장하므로 다른 사용자의 변경을 조용히 덮어쓰지
않습니다.

일괄 변경은 선택한 활성 작업의 상태, 우선순위, 담당자와 라벨을 원자적으로 수정합니다. 일부만
성공하는 상태를 만들지 않으며, 각 작업의 변경 이력과 알림도 동일한 계약을 따릅니다.

## 권한과 무결성

모든 작업 조회와 변경은 조직, 워크스페이스, 프로젝트, 역할과 토큰 기능 범위를 검사합니다. 제한된
작업은 명시적으로 허용된 사용자·그룹·역할만 볼 수 있으며, 보드 수치, 검색, 알림과 웹훅에서도 같은
범위를 지킵니다.

댓글과 구독 변경에는 브라우저 CSRF 보호가 필요합니다. 댓글 수정은 작성자와 행 버전을 검사하고,
이전 내용은 추가 전용 감사 이력에 남습니다. 관계 외래 키와 저장소 수준 직렬화는 다른 프로젝트 연결,
중복과 순환을 막습니다.

관련 문서는 [작업 워크플로](/product/task-workflow), [작업 자동화](/product/task-automation),
[주요 일정과 작업 관리](/guide/work-management)를 참고하세요.
