# Engrove 개발 계획

이 문서는 Engrove의 제품 방향과 구현 경계를 한국어로 설명하는 개요입니다. 데이터 모델의 모든 필드,
API 계약, 단계별 수용 조건까지 포함한 전체 기준 문서는
[영문 개발 계획](/en/product/engrove-development-plan)에서 확인할 수 있습니다.

## 제품 정의

Engrove는 측정, 사양, 근거와 프로젝트 실행을 한 흐름으로 연결하는 셀프 호스팅 엔지니어링 데이터
워크스페이스입니다.

제품이 지키는 약속은 다음과 같습니다.

- 엔지니어링 데이터를 자유로운 테이블에 구조화합니다.
- 값뿐 아니라 단위, 측정 시점과 사양 리비전을 보존합니다.
- 원본 파일이나 외부 시스템 URL에서 판정과 후속 작업까지 추적합니다.
- 주요 날짜와 실행 작업을 분리해 일정의 의미를 명확히 합니다.
- 브라우저와 API가 같은 권한·무결성 규칙을 사용합니다.
- 온프레미스와 사설망에서 운영 가능한 기본 경계를 제공합니다.

## 목표 사용자와 조직

주요 사용자는 시험·검증·신뢰성, 공정·품질·설비·재료 엔지니어와 프로젝트 리드입니다. 초기 목표는
Excel과 공유 드라이브 의존도가 높으며 데이터 표준화와 사설 운영이 중요한 10–100명 규모의 조직입니다.

플랫폼·IT·보안 담당자는 인증, 권한, 배포, 백업과 감사 경계를 관리하고, Reviewer와 Viewer는 필요한
범위에서 결정과 근거를 확인합니다.

## MVP 핵심 흐름

1. 조직과 워크스페이스를 만들고 멤버·그룹·역할을 구성합니다.
2. 샘플, 장비, 재료와 시험 방법을 구성 가능한 테이블로 정의합니다.
3. 단위와 물리 차원을 가진 수치 필드를 추가합니다.
4. 원본 파일 또는 외부 자료 URL을 레코드에 연결합니다.
5. 버전이 있는 사양에 대해 측정 결과를 평가합니다.
6. 실패 결과에서 정확한 근거가 연결된 작업을 만듭니다.
7. 검토, 주요 일정, 작업 보드와 대시보드로 결정을 관리합니다.
8. 감사 이력, API와 웹훅으로 변경과 자동화를 추적합니다.

## MVP 기능 범위

### 구성 가능한 데이터

- 필드 타입, 관계, 필수·선택 규칙을 가진 테이블
- Grid, Gallery, Kanban, Calendar와 Form 뷰
- 저장 필터, 정렬, 그룹, 검색과 요약
- CSV 미리보기·가져오기·내보내기
- 테이블별 멤버·그룹·역할 접근 정책
- 레코드 댓글, 멘션, 검토와 변경 이력

### 엔지니어링 타입

- 단위 레지스트리와 물리 차원
- Decimal 기반 수치 표현
- 측정, 범위, 공차와 사양 리비전
- 당시 사양 리비전에 고정된 평가 결과
- 원본을 덮어쓰지 않는 측정·보정 이력

### 파일과 데이터셋

- 체크섬 검증을 거친 버전별 파일 객체
- 원본과 파생 산출물의 명시적인 계보
- 처리 작업의 내구성 있는 상태와 idempotency
- S3 호환 오브젝트 스토리지
- 다른 서비스가 원본을 관리할 때 URL과 버전 메타데이터만 연결하는 외부 자료

### 프로젝트 실행

- 날짜 하나를 기준으로 하는 주요 일정과 단일 축 타임라인
- 프로젝트별 상태와 전환이 있는 작업
- 보드·목록·달력, 순위, 하위 작업과 차단 관계
- 댓글, 멘션, 구독, 근거 링크와 첨부
- 레코드 검토와 개인 작업함
- 저장된 데이터 뷰에 기반한 차트와 대시보드

### 통합과 운영

- `/api/v1` REST API와 OpenAPI
- 기능 범위와 만료 기간을 가진 개인 API 토큰
- 런타임 의존성이 없는 TypeScript SDK
- HMAC 서명 웹훅과 전달 이력
- 로컬 인증과 OIDC Authorization Code + PKCE
- 백업·복구, 상태 점검, 메트릭과 구조화 로그

## 명시적인 MVP 제외 범위

초기 릴리스는 다음 기능을 충분한 계약 없이 흉내 내지 않습니다.

- 범용 스프레드시트 수식 엔진
- 실시간 다중 사용자 셀 편집
- 복잡한 간트 일정과 자원 최적화
- 임의 Python 코드를 실행하는 사용자 플러그인
- 외부 서비스 원본을 무조건 복제하는 통합
- 정책 없는 물리 삭제
- 내구성 있는 스케줄러가 없는 예약 자동화

## 권장 기술 구조

| 영역         | 선택                            |
| ------------ | ------------------------------- |
| 모노레포     | pnpm workspace와 Turborepo      |
| 웹           | React, TypeScript, Vite         |
| API          | NestJS와 Drizzle ORM            |
| 데이터베이스 | PostgreSQL                      |
| 작업 큐      | Redis와 BullMQ                  |
| 과학 연산    | Python, uv와 별도 worker        |
| 객체 저장소  | S3 호환 스토리지                |
| 배포         | Docker Compose 기반 셀프 호스팅 |
| 문서         | VitePress                       |

웹, API, Node worker와 Python worker는 역할을 분리합니다. API 트랜잭션은 도메인 변경과 outbox를 함께
커밋하고, worker는 웹훅, 알림, 내보내기와 과학 계산을 내구성 있게 처리합니다.

## 핵심 도메인 경계

```text
Organization
└─ Workspace
   ├─ Shared tables and records
   └─ Project
      ├─ Key dates
      ├─ Work and reviews
      ├─ External sources
      └─ Charts and dashboards
```

데이터는 프로젝트의 하위 폴더가 아닙니다. 장비, 샘플과 공급사는 워크스페이스에서 재사용하고, 필요한
레코드에만 프로젝트 컨텍스트를 부여합니다. 프로젝트는 목표를 달성하기 위한 실행 경계입니다.

모든 주요 엔티티는 애플리케이션에서 생성한 UUIDv7을 사용합니다. 사용자에게는 작업 키처럼 안정적이고
읽기 쉬운 식별자를 추가로 제공합니다. 보관, tombstone과 물리 삭제 경계를 분리해 참조와 감사 이력을
보호합니다.

## 권한과 보안 원칙

- 권한은 조직 역할, 워크스페이스·프로젝트 접근과 테이블·작업 수준 제한을 함께 검사합니다.
- 브라우저 세션은 불투명한 서버 세션과 CSRF 보호를 사용합니다.
- 개인 API 토큰은 원문을 저장하지 않고 digest와 기능 범위만 보존합니다.
- 프로젝트 격리는 모든 저장소 쿼리에서 명시적으로 적용합니다.
- 비밀은 로그, 감사 이벤트와 오류 응답에 포함하지 않습니다.
- 파일 다운로드는 짧은 수명의 서명 URL을 사용합니다.
- 변경 충돌은 행 버전으로 감지하고 조용한 덮어쓰기를 허용하지 않습니다.

## 감사와 추적성

감사 이벤트는 누가, 언제, 어떤 범위에서, 무엇을 바꾸었는지 기록합니다. 측정, 사양 평가, 파일 버전,
작업 근거와 검토 결정은 당시의 정확한 참조를 유지합니다. 이후 사양이나 표시 이름이 바뀌어도 과거
결정의 의미가 바뀌지 않아야 합니다.

## 품질 전략

- 단위 테스트: 도메인 규칙, 단위 변환, 권한과 오류 계약
- 통합 테스트: PostgreSQL 트랜잭션, 동시성, outbox와 작업 큐
- 브라우저 테스트: 핵심 흐름, 키보드 접근성과 반응형 레이아웃
- 보안 검사: 의존성, 컨테이너, 비밀과 프로덕션 설정
- 운영 검증: fresh-install 백업·복구와 업그레이드 경로

전체 품질 게이트는 다음 명령으로 실행합니다.

```bash
bash scripts/project-loop.sh
```

## 개발 단계

| 단계    | 주요 결과                     |
| ------- | ----------------------------- |
| Phase 0 | 저장소, 버전, ADR와 운영 기준 |
| Phase 1 | 인증, 조직과 워크스페이스     |
| Phase 2 | 구성 가능한 데이터 모델과 뷰  |
| Phase 3 | 단위, 측정, 사양과 평가       |
| Phase 4 | 파일, 데이터셋과 처리 계보    |
| Phase 5 | 차트와 대시보드               |
| Phase 6 | 작업, 검토와 엔지니어링 흐름  |
| Phase 7 | OIDC와 배포 강화              |
| Phase 8 | 파일럿 운영과 수용 검증       |

각 단계는 구현 코드만이 아니라 테스트, 문서, 마이그레이션, 보안과 운영 근거가 함께 완료되어야
종료됩니다.

## 완료 기준

MVP는 팀이 실제 엔지니어링 흐름을 처음부터 끝까지 수행하고 그 결정을 재현할 수 있을 때 완료됩니다.

- 레코드와 측정을 구조화하고 단위를 검증할 수 있습니다.
- 정확한 원본과 사양 리비전을 찾을 수 있습니다.
- 평가에서 검토와 후속 작업을 만들 수 있습니다.
- 작업과 주요 일정이 실제 완료 상태로 연결됩니다.
- 권한, 감사, 백업과 복구가 운영 환경에서 검증됩니다.
- 브라우저와 API가 같은 결과와 오류 계약을 제공합니다.

상세 엔티티 정의, API 목록과 단계별 수용 조건은
[영문 전체 개발 계획](/en/product/engrove-development-plan)을 기준으로 합니다.
