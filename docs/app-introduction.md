# Engrove 소개

**Engrove는 엔지니어링 데이터와 프로젝트 실행을 연결하는 셀프 호스팅 워크스페이스입니다.**

테이블을 자유롭게 만들 수 있는 데이터베이스의 유연성, Jira와 같은 실행 작업 관리, 시험·측정에
필요한 단위와 사양 판정, 그리고 원본 근거의 추적성을 한 제품 안에서 제공합니다.

## Engrove가 해결하는 문제

엔지니어링 조직의 정보는 보통 여러 시스템에 나뉩니다.

| 정보                  | 흔한 저장 위치        | 실제 문제                                                 |
| --------------------- | --------------------- | --------------------------------------------------------- |
| 샘플·장비·시험 조건   | Excel, 공유 문서      | 구조와 명칭이 사람마다 달라집니다.                        |
| 원본 파일·결과 데이터 | NAS, S3, 장비 PC      | 어떤 결과가 어느 파일에서 나왔는지 찾기 어렵습니다.       |
| 사양과 판정           | 문서, 수식, 개인 시트 | 나중에 어떤 사양 버전으로 판정했는지 재현하기 어렵습니다. |
| 주요 일정             | 캘린더, 발표 자료     | 실행 작업과 연결되지 않아 위험을 늦게 발견합니다.         |
| 후속 작업             | Jira, 메신저, 이메일  | 작업은 남지만 발생 근거와 데이터 맥락이 사라집니다.       |

Engrove의 핵심은 모든 것을 한 화면에 넣는 것이 아니라, **변하지 않는 식별자와 이력으로 서로
연결하는 것**입니다. 레코드에서 관련 파일·측정·평가·작업을 찾을 수 있고, 작업에서도 정확한
엔지니어링 근거로 되돌아갈 수 있습니다.

## 제품의 세 가지 축

### 1. 데이터 라이브러리

워크스페이스가 함께 사용하는 엔지니어링 테이블입니다. 샘플, 장비, 재료, 공급사, 시험 방법처럼
프로젝트를 넘어 재사용되는 구조를 정의할 수 있습니다.

- 필드 타입, 관계, 필수·선택 규칙을 가진 구성 가능한 테이블
- Grid, Gallery, Kanban, Calendar와 저장된 뷰
- 검색, 필터, 정렬, 그룹, 요약과 CSV 가져오기·내보내기
- 테이블별 멤버·그룹·역할 접근 정책
- 댓글, 멘션, 검토 요청과 변경 이력

### 2. 프로젝트

프로젝트는 팀의 실행 맥락입니다. 공유 데이터에 프로젝트 컨텍스트를 더하고, 주요 일정과 작업,
검토, 외부 근거, 대시보드를 한 범위 안에서 운영합니다.

- 날짜 하나가 핵심인 **주요 일정**과 단일 축 타임라인
- 보드·목록·달력, 하위 작업, 차단 관계와 순위를 지원하는 **작업**
- 담당자, 댓글, 구독, 첨부, 외부 URL, 작업 시간과 자동화
- 데이터에 연결된 **검토**, 승인 또는 변경 요청
- 버전이 고정된 차트와 대시보드

### 3. 추적성과 운영

원본과 결정의 연결이 오래 유지되도록 변경을 명시적으로 다룹니다.

- 물리 차원과 허용 단위를 가진 측정 필드
- 수정으로 덮어쓰지 않는 측정·보정 이력
- 사양 리비전과 당시 리비전에 고정된 평가 결과
- 체크섬과 버전이 보존되는 파일·데이터셋
- 행위자와 대상을 남기는 감사 이벤트
- OIDC, 세분화된 권한, 백업·복구와 운영 메트릭

## NocoDB와 Jira 사이에서의 위치

Engrove는 범용 도구의 기능을 복제하는 데서 멈추지 않습니다.

| 관점                      | 범용 데이터베이스 | 범용 이슈 트래커 | Engrove               |
| ------------------------- | ----------------- | ---------------- | --------------------- |
| 유연한 테이블·뷰          | 강함              | 제한적           | 강함                  |
| 작업 워크플로·우선순위    | 제한적            | 강함             | 강함                  |
| 물리 단위와 측정 이력     | 일반 필드로 표현  | 대상 아님        | 일급 도메인 개념      |
| 사양 버전과 판정 재현     | 직접 설계 필요    | 대상 아님        | 기본 추적 모델        |
| 작업과 정확한 데이터 근거 | 링크 중심         | 링크 중심        | 버전·엔티티 수준 연결 |
| 셀프 호스팅과 API         | 제품별 상이       | 제품별 상이      | Community 기본 경계   |

따라서 Engrove는 **“테이블을 만들 수 있는 Jira”**보다 **“데이터에서 결정과 실행까지 근거를
잃지 않는 엔지니어링 운영 공간”**에 가깝습니다.

## 주요 사용자

- 시험·검증·신뢰성 엔지니어
- 공정·품질·설비·재료 엔지니어
- 프로젝트 리드와 엔지니어링 매니저
- 사내 플랫폼, IT, 보안과 품질 시스템 담당자

특히 Excel과 공유 드라이브 의존도가 높고, 10–100명 규모 팀에서 데이터 구조 표준화와
온프레미스·사설망 운영이 중요한 경우에 적합합니다.

## 대표 흐름

1. 워크스페이스에서 샘플과 장비 테이블을 정의합니다.
2. 프로젝트를 만들고 시험 대상을 프로젝트 컨텍스트에 연결합니다.
3. 단위와 허용 범위를 가진 측정 필드를 정의합니다.
4. 원본 파일 또는 외부 시스템 URL을 근거로 연결합니다.
5. 결과를 사양 리비전에 대해 평가합니다.
6. 실패 결과에서 정확한 평가 근거가 연결된 작업을 만듭니다.
7. 주요 일정 타임라인, 작업 흐름, 리뷰와 대시보드로 의사결정을 관리합니다.
8. 감사 이력과 API를 통해 변경과 자동화를 추적합니다.

## 제공 형태

Engrove Community는 AGPL-3.0-only로 제공되는 모노레포입니다.

- React 기반 웹 애플리케이션
- NestJS 기반 REST API와 OpenAPI 문서
- PostgreSQL, Redis, S3 호환 오브젝트 스토리지
- Node 오케스트레이션 워커와 Python 과학 연산 워커
- Docker Compose 기반 개발·프로덕션 배포
- 의존성 없는 `@engrove/sdk` TypeScript 클라이언트

이어서 [빠른 시작](/guide/getting-started)에서 로컬 실행과 첫 탐색 순서를 확인하거나,
[구조와 핵심 개념](/guide/concepts)에서 정보 계층을 자세히 살펴보세요.
