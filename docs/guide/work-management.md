# 주요 일정과 작업 관리

Engrove는 프로젝트의 시간 구조와 실행 작업을 구분합니다. 이 구분은 일정의 의미를 분명하게 하고,
사람이 직접 진행률 숫자를 관리하는 문제를 줄입니다.

## 주요 일정은 날짜 중심입니다

주요 일정은 시작일·종료일을 가진 작업 묶음이 아니라 **그 날짜 자체가 중요한 프로젝트 이벤트**입니다.

예를 들면 다음과 같습니다.

- 설계 동결
- 시제품 입고
- 시험 완료
- 고객 리뷰
- 양산 승인

이 이벤트들은 대개 순서대로 이어지므로 시작일은 이전 주요 일정과 중복되는 경우가 많습니다.
Engrove는 목표 날짜 하나를 중심으로 한 타임라인을 제공하고, 상태·설명·담당자와 관련 작업을
연결합니다.

진행률을 직접 입력하지 않습니다. 대신 연결된 작업의 완료 수를 보여 주므로, 일정 상태와 실제 실행
데이터가 어긋나는 문제를 줄입니다.

## 작업은 실행 단위입니다

작업은 Jira에서 익숙한 흐름을 따르되 엔지니어링 근거를 일급 정보로 다룹니다.

- 프로젝트별 사용자 정의 상태와 허용 전환
- 칸반, 밀도 높은 목록, 달력
- 담당자, 우선순위, 마감일, 라벨과 저장 필터
- 하위 작업과 파생 완료 맥락
- 차단·선행·관련 작업 관계
- 원래 추정 시간, 남은 시간과 작성자별 작업 기록
- 댓글, 멘션, 구독, 첨부 파일과 외부 URL
- 레코드·측정·평가·파일·데이터셋에 대한 정확한 근거 연결

카드를 선택하면 상세 패널에서 바로 수정할 수 있습니다. 카드 자체에는 상태 콤보박스나 반복되는
메뉴를 두지 않아 보드를 빠르게 읽을 수 있고, 이동은 드래그, 키보드 또는 우클릭 메뉴로 수행합니다.

## 작업과 데이터의 연결

실패한 사양 평가에서 후속 작업을 만들면 다음 정보가 한 트랜잭션으로 연결됩니다.

1. 평가 대상 레코드와 필드
2. 측정값과 단위
3. 사용된 사양 리비전과 판정
4. 생성된 작업과 감사 이벤트

따라서 작업 제목만 보고 원인을 추정하지 않아도 됩니다. 작업의 근거에서 정확한 데이터로 이동하고,
레코드에서는 아직 열려 있는 후속 작업을 확인할 수 있습니다.

## 검토와 개인 작업함

모든 의견을 작업으로 만들 필요는 없습니다. 레코드 검토는 검토자 지정, 대화, 승인 또는 변경 요청과
해결 이력을 제공합니다. 개인 작업함은 여러 프로젝트에 흩어진 담당 작업과 요청받은 검토를 한곳에
모아 줍니다.

## 흐름과 자동화

프로젝트 리드는 작업 흐름 인사이트에서 현재 WIP, 오래된 작업, 처리량, 중앙값·P85 사이클 타임과
누적 흐름을 확인할 수 있습니다. 자동화 규칙은 상태 변경 같은 이벤트에 조건을 적용해 작업 갱신,
알림 등의 동작을 트랜잭션 안에서 수행하고 실행 이력을 남깁니다.

세부 계약은 [작업 협업](/product/task-collaboration), [작업 워크플로](/product/task-workflow),
[작업 자동화](/product/task-automation)를 참고하세요.
