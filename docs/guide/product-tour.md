# 화면으로 보는 제품 투어

이 투어는 `force` 프로젝트에서 재료와 시험 데이터를 검토하고, 외부 원본을 추적하며, 주요 날짜와
후속 작업을 관리하는 예제를 사용합니다. 화면마다 **무엇을 입력하는지**, **어떤 판단을 하는지**,
**다음 화면과 어떻게 연결되는지**에 집중합니다.

## 예제 시나리오

한 팀이 알루미늄 부품의 설계 동결과 양산 릴리스를 준비하고 있습니다. 시험 결과와 공급사 성적서는
서로 다른 시스템에 있고, 검토 작업은 여러 엔지니어에게 나뉘어 있습니다.

| 관리 대상   | 이 투어의 예제                                                               |
| ----------- | ---------------------------------------------------------------------------- |
| 프로젝트    | `force`                                                                      |
| 재료 레코드 | Anodized aluminum, Stainless steel 304, Carbon fiber prepreg                 |
| 외부 원본   | SharePoint 성적서, LIMS 시험 실행, Jira 공급사 편차                          |
| 주요 일정   | Concept approval → Design freeze → Prototype validation → Production release |
| 실행 작업   | `Review Demo Run 001 force curve` 등 9개 작업                                |

## 1. 워크스페이스에서 내 범위 확인하기

![워크스페이스 요약과 네 개 프로젝트가 표시된 Engrove 개요](/screenshots/workspace-overview.png)

_워크스페이스 개요는 사용자가 속한 조직 범위와 접근 가능한 프로젝트를 확인하는 첫 화면입니다._

워크스페이스는 멤버십과 공유 데이터의 경계입니다. 왼쪽의 워크스페이스 선택기에서 조직을 바꾸고,
프로젝트 카드를 선택해 실행 맥락으로 들어갑니다. 프로젝트 카드에는 이름만 표시해 내부 키와의
중복을 줄입니다.

**확인 예제**

1. 현재 워크스페이스 이름이 `test`인지 확인합니다.
2. 접근 가능한 프로젝트 중 `force`를 선택합니다.
3. 사이드바의 프로젝트 선택기에도 같은 이름이 표시되는지 확인합니다.

## 2. 프로젝트 개요에서 오늘의 판단 찾기

![프로젝트 KPI, 주의 항목, 작업 진행과 바로가기를 보여 주는 개요](/screenshots/project-command-center.png)

_프로젝트 개요는 별도 보고서가 아니라 실행 화면으로 들어가는 지휘판입니다._

상단 지표로 전체 상태를 훑고, `주의가 필요한 항목`에서 늦거나 막힌 작업을 먼저 확인합니다.
`작업 진행`은 보드 상태를 요약하며, 바로가기는 레코드·검토·주요 일정처럼 자주 쓰는 화면으로
이동합니다.

**판단 예제:** 위험한 주요 일정이 보이면 먼저 연결 작업을 확인합니다. 연결 작업이 없다면 수동
진행률을 입력하는 대신, 일정 달성을 위해 끝내야 할 작업을 만듭니다.

## 3. 단위와 판정이 있는 데이터를 읽기

![세 개 재료 레코드와 수치 차트를 포함한 Material RTA 그리드](/screenshots/engineering-data-grid.png)

_그리드는 스프레드시트의 밀도를 유지하면서 단위, 사양 판정, 관계와 이력을 구조화합니다._

`Material RTA` 뷰에서는 각 재료의 정량 값을 같은 열 기준으로 비교할 수 있습니다. 셀의 작은 차트는
분포를 빠르게 읽게 하고, 상세 계산이나 근거 확인이 필요하면 레코드를 엽니다.

예제 레코드 작성 기준은 다음과 같습니다.

| 필드      | 필수 여부 | 예제 값                           |
| --------- | --------- | --------------------------------- |
| 재료 이름 | 필수      | `Anodized aluminum`               |
| 밀도      | 선택      | `2.70 g/cm³`                      |
| 인장 강도 | 선택      | `310 MPa`                         |
| 공급사    | 선택      | 승인 공급사 레코드 연결           |
| 성적서    | 선택      | 외부 자료 `CERT-AL-6061-042` 연결 |

## 4. 레코드를 떠나지 않고 빠르게 수정하기

![재료 레코드 빠른 보기와 RTA 입력 패널](/screenshots/record-quick-view.png)

_빠른 보기는 그리드의 비교 맥락을 유지한 채 한 레코드의 필드를 수정합니다._

행을 선택하면 오른쪽 패널이 열립니다. 이름처럼 저장에 꼭 필요한 값은 `필수`, 계산·관계·메모처럼
나중에 보강할 수 있는 값은 `선택`으로 표시됩니다. 더 넓은 이력이나 관계 탐색이 필요할 때만 전체
상세 화면으로 이동합니다.

**실무 팁:** 데이터 수집 초기에 선택 필드를 억지로 채우지 마세요. 필수 식별자와 원본 링크를 먼저
저장하고, 측정·검토 과정에서 값을 점진적으로 보강하는 편이 이력의 의미가 명확합니다.

## 5. 원본은 복제하지 않고 위치와 버전을 추적하기

![SharePoint, LIMS와 Jira 원본을 모은 외부 자료 목록](/screenshots/external-sources.png)

_원본이 다른 서비스에서 관리된다면 Engrove에는 URL, 외부 식별자, 리비전과 확인일을 남깁니다._

외부 자료는 파일 저장소를 대체하지 않습니다. 원본 시스템을 권위 있는 출처로 유지하면서 Engrove의
레코드·작업·검토에서 정확한 항목으로 되돌아갈 수 있게 합니다.

| 이름                          | 서비스     | 식별자             | 리비전·상태 | 확인일     |
| ----------------------------- | ---------- | ------------------ | ----------- | ---------- |
| Supplier material certificate | SharePoint | `CERT-AL-6061-042` | Rev C       | 2026-08-12 |
| Qualification test run        | LIMS       | `RUN-2026-0813`    | Final       | 2026-08-13 |
| Supplier deviation SUP-147    | Jira       | `SUP-147`          | Resolved    | 2026-08-11 |

표의 수정·교체·삭제 동작은 아이콘으로 표현되고, 마우스를 올리거나 키보드로 초점을 옮기면 툴팁에서
의미를 확인할 수 있습니다.

## 6. 실행 작업을 보드에서 훑기

![네 개 상태 열과 아홉 개 작업 카드가 있는 칸반 보드](/screenshots/task-board.png)

_카드는 빠른 스캔에 필요한 정보만 보여 주고, 상태 변경은 드래그·키보드·우클릭 메뉴로 처리합니다._

보드에서는 흐름과 병목을 읽습니다. 카드마다 상태 콤보박스나 `…` 메뉴를 반복하지 않으므로 제목,
담당자, 우선순위와 열별 작업량에 집중할 수 있습니다.

**확인 예제:** `Review Demo Run 001 force curve`를 선택합니다. 단순 상태 이동이 목적이면 카드를
옮기고, 설명이나 근거를 확인하려면 상세 패널을 엽니다.

## 7. 작업 상세에서 맥락과 실행을 함께 수정하기

![작업 보드 위에 열린 FORCE-5 작업 상세 패널](/screenshots/task-detail.png)

_Jira처럼 카드를 선택해 같은 화면에서 상세를 열고, URL 전체 화면 전환 없이 수정합니다._

작업 상세에는 실행에 꼭 필요한 제목·상태와 선택적인 설명·우선순위·담당자·마감일을 구분해
표시합니다. 레코드, 사양 평가, 외부 원본을 근거로 연결하면 작업을 받은 사람이 왜 이 일이 생겼는지
바로 확인할 수 있습니다.

좋은 작업 예제는 다음 세 문장으로 충분합니다.

1. **관찰:** Demo Run 001의 힘 곡선에서 예상하지 못한 피크가 발견되었습니다.
2. **판단 기준:** 승인된 시험 방법과 현재 사양 리비전에 대해 재검토합니다.
3. **완료 조건:** 원인을 기록하고, 유효한 결과 또는 재시험 계획을 레코드에 연결합니다.

## 8. 날짜 하나가 중요한 이벤트를 한 축에서 보기

![네 개의 프로젝트 주요 날짜와 상태를 연결한 단일 축 타임라인](/screenshots/key-date-timeline.png)

_주요 일정은 기간을 그리는 간트가 아니라 의사결정 날짜의 순서와 위험을 보여 줍니다._

예제 흐름은 `Concept approval`에서 시작해 `Production release`로 이어집니다. `Design freeze`에는
관련 작업 하나가 연결되어 `0/1`로 표시됩니다. 사용자가 임의의 진행률을 입력하지 않으므로, 작업이
끝나면 일정의 실행 맥락도 자동으로 갱신됩니다.

| 일정                 | 날짜       | 상태    | 해석                         |
| -------------------- | ---------- | ------- | ---------------------------- |
| Concept approval     | 2026-07-15 | 완료    | 요구사항과 구조 승인         |
| Design freeze        | 2026-08-20 | 진행 중 | 도면 릴리스와 시험 구성 동결 |
| Prototype validation | 2026-09-10 | 위험    | 중요 시험 이슈 종결 필요     |
| Production release   | 2026-10-01 | 계획    | 검증 근거 확인 후 양산 승인  |

## 9. 대시보드에서 요약하고 원본으로 돌아가기

![전체 샘플, 합격률, 실패 평가와 최근 데이터셋을 보여 주는 대시보드](/screenshots/dashboard-canvas.png)

_대시보드는 결론을 고정하는 보고서가 아니라, 저장된 뷰와 근거 레코드로 돌아가는 탐색 화면입니다._

전체 샘플 수, 합격률, 실패 평가와 최근 데이터셋을 함께 보면 프로젝트 상태를 빠르게 공유할 수
있습니다. 이상 값을 발견하면 차트에서 필터된 레코드로 내려가고, 필요한 경우 검토 또는 후속 작업을
만듭니다.

## 흐름을 다 확인했다면

이 투어의 핵심은 화면 수가 아니라 연결입니다.

```text
워크스페이스 → 프로젝트 → 레코드 → 외부 원본
                              ↓
                         검토·판정 → 작업 → 주요 일정
                              ↑                ↓
                              └── 대시보드 ────┘
```

다음으로 [빠른 시작](/guide/getting-started)에서 로컬 환경을 실행하거나,
[구조와 핵심 개념](/guide/concepts)에서 각 객체의 소유 범위와 관계를 확인하세요.
