# 구조와 핵심 개념

Engrove의 정보 구조는 **조직 → 워크스페이스 → 프로젝트** 순서로 좁아지고, 데이터는 필요에 따라
워크스페이스에서 공유하거나 프로젝트 컨텍스트로 한정합니다.

## 정보 계층

| 수준         | 책임                   | 대표 요소                                                    |
| ------------ | ---------------------- | ------------------------------------------------------------ |
| 조직         | 사용자와 전역 역할     | 멤버, 그룹, Owner·Admin·Engineer·Contributor·Reviewer·Viewer |
| 워크스페이스 | 팀과 공유 데이터 경계  | 데이터 라이브러리, 접근 가능한 프로젝트, 내 작업             |
| 프로젝트     | 한 목표의 실행 경계    | 주요 일정, 작업, 검토, 외부 자료, 대시보드                   |
| 레코드       | 엔지니어링 대상의 맥락 | 속성, 관계, 측정, 사양 평가, 파일, 댓글, 작업                |

## 데이터는 프로젝트의 하위 폴더가 아닙니다

샘플, 장비, 공급사 같은 데이터는 여러 프로젝트에서 재사용됩니다. 그래서 데이터 라이브러리는
워크스페이스 수준에 있고, 각 레코드는 필요할 때 하나의 프로젝트 컨텍스트를 가질 수 있습니다.

이 모델은 다음 두 요구를 함께 만족합니다.

- 같은 장비나 샘플을 프로젝트마다 복제하지 않습니다.
- 프로젝트 화면에서는 해당 프로젝트와 관련된 데이터만 기본으로 좁혀 봅니다.

테이블별 접근 정책은 전역 역할을 넓히지 않고 더 좁히는 방식으로 작동합니다. 특정 멤버·그룹 또는
최소 역할을 지정할 수 있으며, 보이지 않는 테이블은 직접 URL과 API에서도 동일하게 숨겨집니다.

## 프로젝트는 실행 맥락입니다

프로젝트 선택기는 현재 맥락을 바꾸고, 사이드바에는 그 프로젝트에서 수행할 메뉴만 표시합니다.
별도의 프로젝트 목록 페이지를 반복해서 거치지 않고 워크스페이스 개요에서 검색해 바로 전환합니다.

프로젝트 안의 요소는 역할이 다릅니다.

- **주요 일정:** 특정 날짜가 중요한 순차 이벤트
- **작업:** 담당자와 상태가 있고 실제로 완료해야 하는 실행 단위
- **검토:** 레코드 또는 결정에 대한 승인·변경 요청 대화
- **외부 자료:** 다른 서비스에 있는 원본의 URL, 버전, 공급자 메타데이터
- **대시보드:** 버전이 고정된 데이터 뷰와 차트의 조합

## 원본과 파생 결과

파일과 데이터셋은 같은 것이 아닙니다.

1. 원본 파일은 체크섬과 정확한 버전을 보존합니다.
2. 처리 작업은 원본을 바꾸지 않고 새 데이터셋 또는 파생 결과를 만듭니다.
3. 차트와 평가, 작업은 사용한 정확한 버전을 참조합니다.
4. 외부 시스템이 원본을 관리한다면 파일을 복제하지 않고 안정적인 URL과 메타데이터만 연결할 수
   있습니다.

## 측정과 사양

측정값은 단순 숫자가 아니라 값, 단위, 물리 차원과 관측 시각의 조합입니다. 사양은 리비전으로
관리되고, 평가 결과는 평가 당시 사용한 사양 리비전에 고정됩니다. 사양이 바뀌어도 과거 판정의
근거가 바뀌지 않습니다.

## 보관과 삭제

실무 데이터는 즉시 물리 삭제하지 않습니다. 일반 사용자는 보관과 복원을 사용하며, 참조와 이력이
유지됩니다. 중요한 변경은 행 버전을 이용한 낙관적 동시성 검사로 보호되므로, 다른 사용자의 최신
변경을 오래된 화면이 조용히 덮어쓰지 않습니다.
